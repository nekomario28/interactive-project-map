# README visual research

Status: reviewed for the README refresh on 2026-08-22.

## Goal

Improve the first-screen comprehension and visual credibility of the public repository without turning the README into a badge wall, copying another project's artwork, or hiding the technical trust model.

The review intentionally sampled highly starred open-source repositories with different README styles. Star counts are only rough snapshots and are not used as a quality metric by themselves.

## References reviewed

### Excalidraw

Repository: https://github.com/excalidraw/excalidraw

Observed pattern:

- large product-specific cover image at the top;
- compact navigation row immediately under the cover;
- centered one-sentence value proposition;
- a restrained badge row;
- a second product showcase image before detailed documentation.

Useful lesson: show the product before explaining its implementation.

### Supabase

Repository: https://github.com/supabase/supabase

Observed pattern:

- light/dark-aware visual branding;
- product capabilities before implementation detail;
- a real dashboard screenshot;
- architecture as a visual diagram rather than only prose.

Useful lesson: real output plus an architecture image makes a large technical project easier to scan.

### Appwrite

Repository: https://github.com/appwrite/appwrite

Observed pattern:

- wide hero image;
- very short value proposition;
- a small badge/social row;
- installation path early in the document;
- Mermaid architecture later for technical readers.

Useful lesson: visual hierarchy and technical depth can coexist if the first screen stays simple.

### Zed

Repository: https://github.com/zed-industries/zed

Observed pattern:

- minimal title and only a couple of useful badges;
- direct statement of what the product is;
- installation appears almost immediately;
- little decorative content.

Useful lesson: high-star repositories do not require maximal decoration. Every visual element should carry product or trust information.

### shadcn/ui

Repository: https://github.com/shadcn-ui/ui

Observed pattern:

- extremely compact README;
- a strong one-paragraph product statement;
- detailed content is delegated to the documentation site.

Useful lesson: the README is a landing page and routing layer, not necessarily the complete manual.

## Adopted for Project Galaxy

1. **Real generated map as the hero.** The README uses Project Galaxy's own generated `galaxy.svg`, linked to the interactive demo. No mock screenshot or third-party artwork is required.
2. **Short centered value proposition.** The first screen says what the project produces and why the static-first model matters.
3. **Five-or-fewer useful badges.** CI, Pages, preset count, static-first runtime and license. No visitor counters or decorative technology badge wall.
4. **Direct CTA row.** Generator, live demo, quick start, presets and roadmap are reachable before the long technical sections.
5. **Four compact value cards.** They explain the graph/view model, user ownership, static-first runtime and interactive exploration.
6. **Mermaid architecture.** The old text-only pipeline is expressed visually while retaining the permission/trust explanation below it.
7. **Technical detail remains available.** Presets, validation, action inputs, Cloudflare boundary, verification and credits remain in the README or linked repository docs.

## Explicitly rejected

- copying upstream hero/logo artwork;
- third-party screenshots presented as this project's UI;
- animated decorative GIFs unrelated to real behavior;
- visitor counters, trophy widgets, language badge walls and similar vanity elements;
- dozens of badges that push the actual product below the fold;
- hiding the static-first architecture or token-permission boundary behind marketing copy;
- generating a fake visual mock when the project can show its own real output.

## Licensing and attribution boundary

No implementation code, image asset, logo, screenshot, or README prose was copied from the reference repositories. Their public READMEs were used only to identify layout patterns and information hierarchy. The visual hero shown by this repository is generated by Project Galaxy itself.
