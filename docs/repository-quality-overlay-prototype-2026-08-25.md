## Two ring modes

### Full

The full ring uses eight stable semantic slots:

```text
understandability
verification
reproducibility
maintainability
integrity
interoperability
security-safety
stewardship
```

It preserves dimension identity and represents supports/weakens/neutral/mixed/unknown/optional/N/A/unresolved applicability separately.

### Compact

The compact ring summarizes only the finding distribution across required/recommended target dimensions:

```text
supports
neutral
weakens
mixed
unknown
```

Optional and N/A dimensions do not enter its denominator. Compact mode intentionally does not preserve dimension identity and therefore requires a full/detail view for explanation.

Neither mode emits a Quality score.

## Fixture coverage

The prototype regressions use four bounded cases:

```text
interactive-project-map application
ProjExD_Group10 application
FiveThirtyEight external dataset slice
ProjExD_Group10 with explicit security-safety N/A override
```

Full mode renders eight semantic slots per card with equal repository-core size. Compact mode renders proportional target-finding shares with the same equal core size.

## No-score boundary

The prototype does not consume or render:

- Stars;
- Fork counts;
- Portfolio Prominence;
- a total Quality score;
- a Confidence score;
- rank/tier geometry.

It may display evidence coverage such as:

```text
4/6 interpreted
4/5 interpreted
```

This remains a denominator-aware evidence statement, not merit.

## N/A and unknown remain distinct

In full mode, explicit `not-applicable` uses a gap semantic while applicable unresolved targets remain `quality-unknown`.

In compact mode, N/A leaves the denominator while unknown target findings remain an unresolved share.

Optional evidence remains separately addressable in full detail but cannot inflate core target coverage or compact finding distribution.

## Safety and robustness

Repository labels are XML-escaped before insertion into SVG text.

The generator accepts only v1 eight-slot overlay models and rejects unsupported ring modes. Full and compact modes both keep node core geometry unchanged.

## Bounded local visual reconstruction

Because the execution environment could not resolve GitHub directly, the checked geometry and frozen case states were reconstructed locally for visual inspection rather than claiming an exact workflow-produced artifact.

The full ring reconstruction was inspected at approximately 100%, 50% and 33% scale:

- 100%: supports/weakens and dimension segmentation were readable;
- 50%: broad direction remained readable, but unknown/optional/N/A distinctions weakened;
- 33%: broad direction remained, but individual dimension meaning was no longer self-explanatory.

A compact target-finding distribution reconstruction was then inspected at the same scales:

- 100%: support/weakening/unresolved proportions were immediately readable;
- 50%: the broad distribution remained clear;
- 33%: the broad support/weakening/unresolved pattern still survived materially better than the full eight-slot encoding.

This visual evidence is why the contract now separates:

```text
full    = dimension identity / detail
compact = small-scale distribution summary
```

It is **not** production visual acceptance, because it did not inspect an artifact generated by the exact branch head inside CI or the real profile renderer.
